# ST C++ preparation

Год подготовки к студенческой C++ стажировке в Spectral::Technologies.
Период: октябрь 2026 — октябрь 2027. Рабочая нагрузка: 10–12 часов в неделю, меньше во время сессий.

## Как храним работу

Основное место — приватный GitHub-репозиторий `st-cpp-prep` и его рабочая копия на своём компьютере. Здесь находятся план, упражнения, заметки, ошибки и результаты пробных интервью. Законченные пет-проекты будут в отдельных репозиториях; ссылки добавляем в `projects/README.md`.

Архив — стартовая копия файлов, не созданный удалённый репозиторий. У архива нет Git-истории и настроенного origin. Перед первой отправкой нужно создать пустой GitHub-репозиторий и выполнить команды из `docs/git-workflow.md`.

| Файл / каталог | Что хранит |
|---|---|
| `CURRENT.md` | Короткий указатель: активная задача, окружение и ближайший шаг |
| `current/CURRENT-<NN>.md` | Подробный прогресс конкретного упражнения, например `current/CURRENT-01.md` |
| `ROADMAP.md` | Полная годовая программа и источники |
| `exercises/` | Задания, собственные решения и тесты |
| `notes/theory/`, `notes/therory/` | Личные заметки студента; агенты их не читают и не изменяют |
| `notes/generated-theory/` | Учебные материалы, которые создаёт и обновляет только `theory_author` |
| `logs/` | Журнал занятий и ошибок |
| `interviews/` | Результаты пробных интервью и слабые темы |
| `projects/README.md` | Ссылки на отдельные проекты |
| `tools/environment_check.cpp` | Проверка компиляции и запуска C++20 |

## Как продолжаем между чатами

В начале работы читаем короткий `CURRENT.md`, затем только указанный там `current/CURRENT-<NN>.md` и нужные файлы активной задачи. Архивные файлы других упражнений без необходимости не читаем. Если ассистенту доступен этот приватный репозиторий через подключённый GitHub, можно передать ссылку на него. Иначе прислать эти два CURRENT-файла, код задачи и вывод компилятора/тестов.

Доступ к файлам и обновление репозитория проверяются в конкретной сессии. Диалог сам по себе не создаёт commit/push и не гарантирует сохранение прогресса в GitHub. Обновления считаются сохранёнными после успешной отправки в origin.

В конце занятия: решение/заметка → подробное обновление `current/CURRENT-<NN>.md` → короткое обновление `CURRENT.md` → commit → push. В файлах фиксируем реальные результаты; непроверенное помечаем как непроверенное.

## Старт

1. Создать приватный `st-cpp-prep`, перенести содержимое архива и отправить первый commit.
2. Записать свою ОС, компилятор, опыт C++ и доступные часы в `CURRENT.md`.
3. Выполнить проверку окружения.
4. Начать `exercises/00-diagnostic/TASK.md` с первого вопроса. Не смотреть готовые решения до собственной попытки.
5. После диагностики перейти к `exercises/01-unique-fd/TASK.md`.

## Материалы теории и опрос

Для подготовки материала попроси основной агент использовать `theory_author`,
например: «Поручи theory_author подготовить теорию о времени жизни объектов
в C++20 в notes/generated-theory/object-lifetime.md».
Конфигурация роли: `.codex/agents/theory_author.toml`.
Папку и учебный файл создаёт сам автор при первом таком поручении.
Модель и уровень рассуждения наследуются от вызывающего агента.

Другие агенты не читают и не изменяют эту папку. Для опроса самостоятельно
передай выбранный файл в отдельный чат и попроси задавать вопросы по одному,
проверять ответы и давать задачи на применение. Результат опроса можно
сообщить наставнику для планирования практики; сам файл передавать ему
не требуется. Личные заметки остаются отдельными и недоступными всем агентам.

Разделение закреплено инструкциями, а не правами файловой системы:
[документация OpenAI о конфигурации агентов](https://learn.chatgpt.com/docs/agent-configuration/subagents).

## Проверка окружения

Нужны Git, CMake 3.20+ и компилятор с поддержкой C++20. GCC или Clang удобны для будущих Linux/POSIX задач. Для Windows практику по Linux можно вести в WSL2; конкретную установку подберём после уточнения ОС.

Сборка через CMake:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

Прямой запуск для GCC:

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic tools/environment_check.cpp -o environment_check
./environment_check
```

Успех этой проверки подтверждает компиляцию/запуск C++20, а не знание языка. Оценка навыков происходит на диагностических заданиях.

Учебный процесс: собственная попытка → объяснение → ревью → исправление → повторная проверка. Ассистент помогает вопросами, подсказками и ревью; исходная реализация упражнения остаётся работой студента.
