# LRU-кеш

Однопоточный кеш C++20 с ключами `int`, значениями `std::string` и фиксированной вместимостью. Реализация — `lru_cache.hpp`, сценарные тесты — `test.cpp`. Копирование и перемещение кеша запрещены.

## Структуры данных и владение

Записи хранятся в `std::list<std::pair<int, std::string>>`. Каждый узел содержит ключ и строку. Начало списка соответствует самой недавно использованной записи (MRU), конец — самой давно использованной (LRU).

Для поиска используется `std::unordered_map<int, ListIt>`, где `ListIt` — итератор списка. Таблица связывает ключ с узлом, в котором находится его значение. Ключ дополнительно хранится в списке, чтобы при вытеснении хвостового узла можно было удалить соответствующую запись таблицы без полного перебора.

Кеш через список владеет строками. Итераторы в таблице служат связями с узлами, а результат `get` — заимствованный указатель на строку. Выбранная схема позволяет находить записи через таблицу и переставлять существующие узлы списка без пересоздания строк.

## Инварианты

На входе в публичные операции и после их завершения, включая выход с исключением:

- Размеры списка и таблицы равны и не превышают вместимость.
- Каждый ключ представлен ровно одним узлом списка и одной записью таблицы.
- Итератор в таблице обозначает живой узел списка с тем же ключом.
- В начале списка находится MRU-запись, в конце — LRU-запись.
- Вместимость не меняется после создания кеша.

Внутри вставки список временно может содержать новый узел, которого ещё нет в таблице. Если добавление в таблицу не удалось, этот узел удаляется до передачи исключения вызывающему коду.

## Операции

### get

Таблица ищется через `find`. Если ключ отсутствует, возвращается `nullptr`, порядок не меняется. При успехе `splice` переносит найденный узел в начало того же списка. Затем возвращается адрес строки внутри узла.

### put

При нулевой вместимости операция сразу завершается.

Если ключ существует, его узел переносится в начало, а строке присваивается новое значение. Размер не меняется, другие записи не вытесняются, объект строки сохраняется.

Для нового ключа в заполненном кеше сначала вытесняется LRU-запись. Затем в начало списка добавляется пара ключ/строка и в таблицу записывается итератор на неё. При исключении вставки в таблицу новый узел удаляется через `pop_front`, после чего исключение передаётся дальше через `throw;`.

### erase и вытеснение

`erase` находит ключ в таблице. Если его нет, возвращает `false`. Иначе удаляет узел списка и запись таблицы, затем возвращает `true`.

`erase_last_usage` получает последний узел через `std::prev(list_.end())`, извлекает ключ и вызывает `erase`. Этот помощник вызывается только для полного кеша положительной вместимости, поэтому список в этот момент непустой.

### size и capacity

`size` возвращает размер списка, `capacity` — вместимость, установленную конструктором. Обе операции объявлены `noexcept` и не меняют порядок.

## Инвалидирование и lifetime

Вставки в список и перенос узла через `splice` сохраняют итераторы и адреса существующих элементов. Удаление узла инвалидирует доступ к нему. Поэтому вместе с узлом удаляется и соответствующая запись таблицы.

Rehash таблицы инвалидирует её собственные итераторы, но не итераторы списка, которые хранятся как значения таблицы. В текущей вставке после возможного rehash прежний итератор таблицы не используется.

Указатель из `get` остаётся действительным при обращениях к кешу, вставке и удалении других ключей, пока его собственная запись не вытеснена. При обновлении этого же ключа сохраняется объект `std::string`, и старый указатель позволяет прочитать новое значение.

Присваивание строке может заменить её внутренний буфер символов. Указатель на объект строки и указатель на символы из `c_str()` имеют разные гарантии; контракт кеша относится только к объекту строки.

Удаление или вытеснение записи и уничтожение кеша инвалидируют указатель. Повторная вставка того же ключа не восстанавливает старый указатель. После инвалидирования указатель не разыменовывается. Чтение через ранее полученный указатель не обновляет LRU-порядок. `const` запрещает менять строку через этот указатель, но не мешает кешу обновлять её самому.

## Сложность и память

Пусть n — число записей. Стоимость работы со строками учитывается отдельно.

| Операция | Ожидаемая сложность по n | Худшая сложность по n |
|---|---|---|
| `get` | O(1) | O(n) |
| `put` | O(1) | O(n) |
| `erase` | O(1) | O(n) |
| `size`, `capacity` | O(1) | O(1) |

Хеш-таблица обеспечивает среднее O(1) для поиска, вставки и удаления ключа; в худшем случае эти операции линейны. У списка вставка одного узла, удаление по известному итератору и перенос одного узла через `splice` имеют O(1). Поиска по списку нет.

Копирование аргумента-строки длины L требует O(L), даже если работа со структурами кеша занимает ожидаемое O(1). Передача строки по значению может вызвать копирование ещё до входа в `put`; передача временной строки или перемещение имеют другую стоимость. Создание и освобождение строкового содержимого учитываются отдельно от числа записей.

Служебная память — O(capacity): узлы списка, записи и бакеты таблицы. Дополнительно хранится память строк. Неограниченная история удалённых ключей не сохраняется.

## Исключения

`put` обеспечивает базовую гарантию: после исключения структуры согласованы, ресурсы не утекли, размер не превышает вместимость, кеш пригоден к дальнейшему использованию. Прежние данные могут быть потеряны.

Возможные места отказа:

- Создание аргумента `value` до входа в метод: состояние кеша ещё не менялось.
- Выделение узла списка: вставка не завершается. Если до неё уже вытеснена старая запись, она не восстанавливается, но оставшиеся структуры согласованы.
- Выделение записи или перестроение таблицы: вставка нового ключа может бросить. Обработчик удаляет только что добавленный узел списка и повторно выбрасывает исключение.

Для текущих типов `int`, `std::string` и стандартных аллокаторов перенос одного узла через `splice` и перемещающее присваивание строки при обновлении не бросают. Присваивание итератора списка после успешного получения записи таблицы также не добавляет точки отказа. Ошибки выделения памяти не подавляются.

Сильная гарантия для вставки в полный кеш не обеспечивается: LRU-запись удаляется до попытки выделить память под новую. RAII отвечает за освобождение ресурсов контейнеров, а явный откат нужен для восстановления связи списка с таблицей.
