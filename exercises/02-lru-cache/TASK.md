# 02. LRU-кеш

## Цель и объём

Следующий компонент после `01-unique-fd`: однопоточный кеш с ограниченной вместимостью и политикой Least Recently Used. Он тренирует выбор контейнеров, связь нескольких структур данных, инвалидирование итераторов, время жизни заимствованного результата и гарантии исключений.

Ориентир — 4–6 занятий по 60–90 минут; это оценка, а не срок сдачи. C++20, ключи `int`, значения `std::string`. Шаблонную версию и измерение производительности оставляем для следующих упражнений.

## Что означает LRU

Успешный `get` и любой `put` существующего ключа делают этот ключ самым недавно использованным. Новый ключ становится самым недавно использованным при вставке. Если для нового ключа места нет, вытесняется самый давно использованный ключ.

Неудачный `get`, `erase` отсутствующего ключа и запросы `size`/`capacity` не меняют порядок использования. Простое чтение ранее полученного указателя также не обновляет порядок.

## Публичный интерфейс

Это спецификация интерфейса, а не готовая реализация:

```cpp
class LruCache {
public:
    explicit LruCache(std::size_t capacity);

    const std::string* get(int key);
    void put(int key, std::string value);
    bool erase(int key);

    std::size_t size() const noexcept;
    std::size_t capacity() const noexcept;

    LruCache(const LruCache&) = delete;
    LruCache& operator=(const LruCache&) = delete;
    LruCache(LruCache&&) = delete;
    LruCache& operator=(LruCache&&) = delete;
};
```

Для первой версии копирование и перемещение явно запрещены. Это фиксирует объём задачи; поведение копии структур, хранящих итераторы, разберём отдельно. Другие публичные методы не нужны.

## Контракт операций

- Конструктор создаёт пустой кеш. Вместимость задаётся один раз.
- `get(key)` возвращает `nullptr` при отсутствии ключа. При успехе возвращает указатель на строку внутри кеша и обновляет порядок использования.
- `put(key, value)` вставляет новый ключ или заменяет значение существующего. Обновление существующего ключа не увеличивает размер и не вытесняет другие записи.
- При вставке нового ключа в заполненный кеш вытесняется ровно одна LRU-запись.
- Вместимость 0 допустима: `put` ничего не сохраняет, `get` возвращает `nullptr`, `erase` возвращает `false`.
- `erase(key)` возвращает `true`, если запись существовала и удалена; иначе `false`.
- `size()` — количество записей, `capacity()` — исходная вместимость. После завершения любой операции `size() <= capacity()`.
- Отрицательные ключи, включая крайние значения `int`, допустимы. Пустая строка — обычное сохранённое значение, а не признак отсутствия.

### Владение и время жизни результата

Кеш владеет строками; результат `get` — заимствованный указатель на объект `std::string`.

Указатель на существующую запись остаётся действительным при `get`, вставках других ключей и удалении других ключей, если сама запись не вытеснена. Обновление значения этого же ключа через `put` сохраняет действительность указателя: он указывает на строку с новым значением.

Удаление или вытеснение этого ключа и уничтожение кеша инвалидируют указатель. Последующая вставка того же ключа не восстанавливает старый указатель. После инвалидирования не разыменовывай его даже ради теста. Гарантии относятся к указателю на объект строки; указатели на её символы не входят в этот контракт.

### Сложность и исключения

- `get`, `put`, `erase`: ожидаемое O(1) по числу записей; `size`/`capacity`: O(1).
- Стоимость создания, копирования и уничтожения строк учитывай отдельно. Не называй копирование строки произвольной длины O(1).
- Память: O(capacity) для служебных структур плюс память сохранённых строк. Кеш не должен хранить неограниченную историю удалённых ключей.
- В README отдельно укажи худшую сложность выбранных контейнеров.
- Не подавляй ошибки выделения памяти ради видимости успеха. При исключении из `put` кеш должен оставаться согласованным, без утечек и пригодным для дальнейшего использования; ограничение размера сохраняется. Для этой версии допустима базовая гарантия: прежние данные могут измениться.
- Опиши места, где операция может бросить исключение, и почему там сохраняются инварианты. Инъекция отказов и сильная гарантия — дополнительные этапы, не обязательные для завершения этой версии.
- Потокобезопасность в этом упражнении не требуется.

## Контрольный пример

Вместимость 2. В таблице порядок показан от самого недавно использованного к самому давно использованному.

| Операция | Результат | Порядок ключей |
|---|---|---|
| `put(1, "A")` | сохранена запись 1 | 1 |
| `put(2, "B")` | сохранена запись 2 | 2, 1 |
| `get(1)` | строка `"A"` | 1, 2 |
| `put(3, "C")` | вытеснен ключ 2 | 3, 1 |
| `get(2)` | `nullptr` | 3, 1 |
| `put(1, "AA")` | значение заменено | 1, 3 |
| `erase(3)` | `true` | 1 |

## Обязательные проверки

- Пустой кеш и отсутствующий ключ.
- Вместимость 0 и вместимость 1.
- Вставка до заполнения и вытеснение при переполнении.
- Успешный `get` меняет будущий выбор вытесняемой записи.
- Неудачный `get` не меняет порядок.
- Обновление существующего ключа меняет значение и порядок, но не размер.
- Обновление в заполненном кеше не вытесняет другую запись.
- Удаление существующего и отсутствующего ключа; повторное удаление.
- Повторная вставка ранее удалённого ключа.
- Пустые строки, отрицательные и крайние ключи.
- Заимствованный указатель сохраняется при допустимых операциях, включая обновление его ключа. Не читать указатели после удаления/вытеснения.
- Размер остаётся в пределах вместимости после каждой операции.

Для эталонной модели разрешён линейный поиск: она должна быть проще основной реализации и независимо выражать контракт. На фиксированном seed сравни последовательности `put/get/erase` при нескольких малых вместимостях. Сравни значения, результаты удаления и размер после операций; корректность выбора вытеснения должна проявляться в наблюдаемых результатах. Проверочный запрос `get` сам меняет порядок: эталон и реализация должны получать одинаковую последовательность операций. При несовпадении печатай seed, вместимость и последовательность для воспроизведения.
